# Лабораторная работа №3. Объектно-ориентированное программирование

Классы структур данных из ЛР1/ЛР2 на **C++** (`cpp/`) и **Go** (`go/`), юнит-тесты (покрытие > 85 %), benchmark,
HTML-отчёты о покрытии, линтеры, сериализация/десериализация (бинарный и текстовый форматы).

Структуры: массив, односвязный список, двусвязный список, очередь, стек, хеш-таблица (цепочки), дерево
(Complete Binary Tree — вариант из ЛР1/ЛР2).

## Запуск

| | C++ (`cd cpp`) | Go (`cd go`) |
|---|---|---|
| тесты | `make test` (Google Test) | `make test` (`testing`) |
| покрытие + HTML | `make coverage` → `coverage-html/index.html` | `make cover` → `coverage.html` |
| benchmark | `make bench` | `make bench` |
| линтер | `make lint` (clang-tidy; сборка с `-Wall -Wextra -Wpedantic -Werror`) | `make lint` (gofmt + go vet) |
| демо сериализации | `make run` (файлы в `out/`) | `make run` (файлы в `out/`) |

Зависимости C++: `brew install googletest lcov cmake llvm`. Сначала `make run` в `cpp`, затем в Go
выполняется тест `TestReadFilesWrittenByCpp`, который читает файлы, записанные C++ (форматы совпадают).

## Результаты

* C++: 63 теста, покрытие строк **98.8 %** (661/669), функций 96.6 %; clang-tidy без замечаний.
* Go: покрытие операторов **98.8 %**; `gofmt`/`go vet` без замечаний.

## Архитектура ООП

* `ISerializable` — интерфейс (4 чисто виртуальных метода: `saveBinary/loadBinary/saveText/loadText`).
* `IContainer` — абстрактный класс-наследник; реализует сериализацию по шаблону «шаблонный метод»
  через 5 примитивов: `typeName, size, toVector, clear, append`. Конкретный класс реализует только их.
* Конкретные классы: `MyArray`, `SinglyLinkedList`, `DoublyLinkedList`, `Queue`, `Stack`, `HashTable`,
  `CompleteBinaryTree`. `Stack` и `Queue` — **композиция** над `SinglyLinkedList` (у списка есть хвост → `push/pop` за O(1)).
  `HashTable` — композиция: корзины `std::vector<SinglyLinkedList>`.
* Правило пяти реализовано для классов с владеющими указателями (копирование, перемещение, деструктор);
  ошибки — исключения `std::out_of_range`/`std::runtime_error` (в Go — `ErrIndex`/`ErrEmpty`/`error`), а не вывод в `cout`.
* Загрузка атомарна: при ошибке формата содержимое контейнера не меняется.

## Форматы сериализации (одинаковы в C++ и Go)

```
бинарный:  "LR3B" | u8 len(typeName) | typeName | u32 count | count × (u32 len | bytes)     (little-endian)
текстовый: "LR3T <typeName> <count>\n" + по строке на элемент; \ → \\, перевод строки → \n, CR → \r
```

Порядок `toVector`: массив/списки/очередь — от головы; стек — от дна к вершине; дерево — по уровням;
хеш-таблица — по корзинам (порядок не важен, это множество).

## Сложность (BigO)

| Структура | Добавление | Удаление | Доступ по индексу | Поиск |
|---|---|---|---|---|
| Массив | конец O(1) амортиз., по индексу O(n) | O(n) | O(1) | O(n) |
| Односвязный список | голова/хвост O(1); до/после значения O(n) | голова O(1); хвост O(n); по значению O(n) | O(n) | O(n) |
| Двусвязный список | голова/хвост O(1); до/после значения O(n) | голова/хвост O(1); по значению O(n) | O(n) | O(n) |
| Стек | push O(1) | pop O(1) | top O(1) | O(n) |
| Очередь | push O(1) | pop O(1) | front O(1) | O(n) |
| Хеш-таблица (цепочки) | O(1) средн., O(n) худш. | O(1) средн. | — | O(1) средн. |
| Complete Binary Tree | O(n) (поиск свободной позиции в ширину) | — (вместо удаления `isComplete`, O(n)) | — | O(n) |

Измерения подтверждают оценки: `make bench` (C++ — время при росте n; Go — `ns/op`, `allocs/op`).
